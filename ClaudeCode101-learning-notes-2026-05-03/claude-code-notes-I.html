Claude Code 学习笔记 I

从零理解 Agent、Agent Loop 与 Claude Code
模块一

认知地基 — 先把概念理清

在动手用 Claude Code 之前，有几个概念值得先搞清楚。它们乍看相似，却有本质区别——混淆了这些概念，后面越学越绕。本模块的目标不是背定义，而是建立一套能区分事物的直觉。

1.1　Claude.ai 和 Claude Code——同一个 AI，两种工作方式

很多人第一次听到 Claude Code，会以为它是一个独立的、更强大的 AI 模型。其实不是。它们背后用的是同一个语言模型，区别在于这个模型被赋予了什么能力、工作在什么环境里。

维度Claude.ai（网页对话）Claude Code（终端/IDE）
底层模型ClaudeClaude（同一个）
能访问什么只有对话窗口里的内容你的文件、终端、整个代码库
能做什么生成文字、回答问题、分析粘贴进来的代码直接读写文件、运行命令、搜索网络
工作方式你问，它答，循环由你驱动它自主循环，直到任务完成
定位对话助手AI Agent
核心差异一句话：Claude.ai 是你在和 AI 聊，Claude Code 是 AI 在帮你干活——它有手，能直接动你的文件和终端。

1.2　Agent 不是一个开关，而是一条光谱

学习 Claude Code 时，文档会反复说它是"AI Agent"。但如果你追问"Agent 到底是什么"，很容易掉进一个误区：以为 Agent 是一种工具的分类——要么是 Chatbot，要么是 Agent，非此即彼。

更准确的理解是：Agent 是一个程度的概念，像一条光谱。不同的 AI 工具在这条光谱上占据不同的位置，取决于它能自主完成多少连续步骤、需要多少人类介入。

← 纯 Chatbot（每步都要人驱动） 完全自主 Agent →
例子自主程度需要人介入的频率
FAQ 机器人极低每句话都要人发起
Claude.ai 对话低每个问题都要人推进
Claude.ai + 工具调用中低每个任务段都要人确认
Claude Code（默认模式）中高关键操作前询问权限
Claude Code（自动接受）高只在任务完成时介入
Claude.ai 现在也能联网搜索、也能分析文件——它算不算 Agent？
算"部分 Agent"，但程度比 Claude Code 低得多。关键不在于"能不能调用工具"，而在于谁在驱动循环：Claude.ai 每次都需要你提问来推进；Claude Code 收到一个任务后，会自己规划步骤、调用工具、验证结果、反复迭代，直到完成——整个过程你不用一直盯着。

1.3　Agent 的三个核心特征

光谱上越靠右，就越接近"真正的 Agent"。判断一个 AI 工具在光谱上位置的标准，是它具备以下三个特征的程度：

1
多步规划——把复杂目标拆解成步骤序列

不只是回答"下一步怎么做"，而是能自己看清整条路：先做 A，再做 B，如果 B 失败就走 C。这是真正自主的前提。

2
自主执行——做→检查→修正→再做的循环

不等你每步确认，而是自己跑完整个循环：执行一步、观察结果、判断是否达标、不达标就修正再试。这个循环就是 Agent Loop（下一模块详讲）。

3
工具使用——主动判断何时调用外部能力

不只是"会用工具"，而是自己决定什么时候需要用、用哪个工具、如何处理工具返回的结果。工具是 Agent 的手和眼，让它能接触现实世界。

两个常见误解要破掉：
"有记忆功能 = Agent"——❌ 记忆只是存档，不等于能自主规划和执行。
"能调用工具 = Agent"——❌ 如果每次调用都要你发指令，驱动循环的还是你，不是它。
那 Claude Code 具体在哪里体现这三个特征？
以"帮我实现用户登录"为例：Claude Code 会自己规划（前端表单 → 后端验证 → 写测试）、自主执行（写文件、运行测试、发现报错、修复、再跑测试）、调用工具（读文件工具、写文件工具、bash 命令工具），整个过程不需要你每步发令。这三点同时成立，所以它是 Agent。
模块二

Agent Loop 原理 — 循环是 Agent 的心脏

上一模块说，Agent 的核心特征之一是"自主执行——做→检查→修正→再做的循环"。这个循环有一个专门的名字：Agent Loop（也叫 Agentic Loop）。理解它，Claude Code 的所有行为就有了根基。

2.1　没有循环，人就是那个循环

想象这样一个场景：你有一个极其聪明的助手，能推理代码、规划方案、写出完美的答案——但它没有手，什么都碰不了。每次它说"运行这个命令"，你就得自己去跑，把输出结果粘贴回来；它说"修改第 12 行"，你就得自己去改，再告诉它改完了。

这种模式下，你就是那个循环。一两步还好，但真实任务往往需要 10、20 甚至 50 次工具调用，全靠人工中转完全不现实。

Agent Loop 解决的核心问题：把"人工中转"这一步自动化——让代码代替你驱动循环，把工具执行结果自动喂回给模型，不需要人在中间传话。

2.2　Agent Loop 的四个步骤

整个循环可以拆成四步，周而复始，直到任务完成：

1
你输入 Prompt——任务进入循环

你的提问或指令成为对话的第一条消息，循环从这里启动。

2
模型回应——文字或工具调用

模型读取完整的对话历史，返回两种结果之一：纯文字回答（任务完成），或者一个工具调用指令（"运行这个命令"、"读这个文件"）。

3
执行工具——接触真实世界

外层程序（harness）拦截工具调用指令，真正去执行它：运行 bash 命令、读写文件、搜索网络……并收集执行结果。

4
Write-back——把结果写回对话，再次循环

将工具执行的真实结果作为新消息追加到对话历史中，然后跳回第 2 步，让模型看到结果后决定下一步。

循环什么时候停下来？会不会一直转？
循环的终止条件很明确：当模型的回应是纯文字（而非工具调用）时，说明它认为任务完成了，循环自然结束。所以不会无限转——模型自己决定"我做完了"。如果任务描述不清晰，也可以随时手动打断它。

2.3　Write-back——整个设计最关键的一步

四个步骤里，最容易被忽视、却最重要的是第四步：Write-back。

语言模型本身是"无状态"的——每次被调用，它只能看到传给它的消息历史，看不到外部世界发生了什么。如果工具执行了一个命令，但结果没有写回对话历史，模型就完全不知道发生了什么，只能凭空猜测。

Write-back 的作用：把"真实世界的反馈"注入模型的视野。模型说"运行测试"，测试跑完报了错，错误信息通过 write-back 出现在对话历史里，模型才能看到、才能据此修正。没有 write-back，模型就是盲的。

这也解释了为什么 Agent 能"自主迭代"：每一轮工具执行的结果都被写回来，模型始终能看到最新的真实状态，从而做出有依据的下一步决策——整个过程不需要人介入。

我不会编程，需要理解 write-back 的技术细节吗？
不需要。只要记住一件事：Claude Code 之所以能自己发现错误并修复，是因为每次工具执行的结果都会自动反馈给它。它不是在猜，而是真的"看到"了测试失败、报错信息，然后据此调整。这就是 write-back 带给你的体感。
"harness"是什么意思？
Harness 直译是"驾驭系统"，在这里指包裹在模型外面的那层管理代码——负责维护对话历史、检测工具调用、真正去执行工具、把结果写回来。Claude Code 本身就是一个 harness。你不需要自己写它，但理解它的存在，能帮你明白谁在驱动循环：不是模型，而是 harness 在外面不断转圈，模型只负责每次被调用时给出判断。
模块三

工作原理 — Context、Tools、Permission

知道 Claude Code 是什么之后，下一个问题是：它怎么工作？这一模块从三个机制入手——模型的记忆边界、与世界交互的手段、以及你对它的控制权。

3.1　Context Window（上下文窗口）— 模型的工作记忆

模型在工作时，有一个有限的「视野范围」，叫做 Context Window（上下文窗口）。你可以把它理解成工作台的桌面空间——桌面越大，能同时摊开的东西越多，但总有上限。

对话历史、读入的代码文件、工具执行结果……所有这些都占用上下文窗口。当窗口快满时，Claude Code 会自动做 Compaction（上下文压缩）：把较早的对话历史压缩成摘要，保留关键信息，腾出空间继续工作。

长对话要注意上下文。如果你发现 Claude Code 开始「忘事」或重复之前已解决的问题，很可能是上下文被压缩了。这时候可以开新会话，或者把关键信息写进 CLAUDE.md 文件，让它在跨会话中保持记忆。
上下文窗口越大越好吗？
更大的 Context Window 确实意味着模型能「记住」更多内容。但这不是越大越好——更大的上下文意味着每次调用费用更高、响应更慢。Claude Code 的设计目标是在有限窗口内高效工作：它会主动搜索只读取相关文件，而不是把整个项目都塞进去。

3.2　Tools（工具）— 模型与世界交互的手段

模型本身只能「说话」——是 Tools（工具） 赋予了它读、写、执行的能力。没有工具，Claude Code 就只是一个问答对话框；有了工具，它才能真正「做事」。Claude Code 配备了四类工具：

工具类型具体行为你的感受
读取代码库 搜索文件、阅读源码、检索 Git 历史 它能理解你的整个项目，而不只是你粘贴过来的片段
编辑文件 创建、修改、删除文件 直接改代码，不需要你手动复制粘贴
运行命令 执行终端命令、跑测试、安装依赖 它能看到命令执行的真实结果，自己发现并修复错误
搜索网络 查询最新文档、搜索错误信息 知识不局限于训练截止日期，能查到最新内容
工具是 Agent Loop 的执行层。回想模块二的循环：模型决定调用哪个工具 → Harness 真正去执行 → 结果 write-back 回对话。工具就是这个循环里「真正触碰现实」的那一步。

3.3　Permission（权限）— 你对 Claude Code 的控制粒度

Claude Code 在采取行动前，总是需要某种形式的「授权」。这套授权机制叫做 Permission（权限），通过三种模式来控制——在输入框左下角按 Shift + Tab 可以在三种模式之间循环切换：

模式英文标识Claude Code 能做什么何时切换到这个模式
默认模式
（即逐步审批）		 Default / Approval 读 + 写 + 执行，每步操作都需要你确认才继续 任务清晰，但想逐步确认每一步；学习阶段首选
自动接受模式 Auto-accept 读 + 写 + 执行，文件编辑自动通过；高风险操作仍会询问 信任任务，希望减少打断、让它流畅连续执行
计划模式 Plan Mode 只读，制定计划但不执行任何修改 第一次接触新任务，或执行到一半想重新审视方向
模式不是一次性选择。按 Shift + Tab 随时切换。同一个任务里可以多次切换——先用 Plan Mode 探索，切到 Default 执行关键步骤，再切到 Auto-accept 跑收尾工作。
模块四

日常工作流 — Explore → Plan → Code → Commit

如果你只从这份笔记里带走一件事，就带走这个工作流。大多数人会跳过前两步直接让 Claude Code 写代码——这样做并非不行，只是后期纠偏的成本会更高。设计逻辑是：在付出最低代价的阶段做最多的思考，在不可逆的阶段做最少的意外。

E
Explore（探索）— 建立现状地图

切换到 Plan Mode，提问：「这个功能目前在哪里实现？」「如果我要加 X，会影响哪些文件？」Claude Code 只读不写，自由探索代码库和 Git 历史。完成信号：你知道「要动哪里」。

P
Plan（计划）— 对齐方向，零代价纠偏

仍在 Plan Mode，让 Claude Code 列出：要修改哪些文件、需要新增哪些依赖、实现步骤、潜在风险。这是最佳纠偏时机——代码还没动，改方向的代价为零。完成信号：方案经你审阅并批准。

C
Code（编码）— 执行、验证、修复

批准计划后切换到 Default 或 Auto-accept，Claude Code 按步骤修改文件、运行测试、处理报错。三个技巧：给出成功标准（「用户能切换深色模式，刷新后保持偏好」比「加个深色模式」清晰得多）；提供测试套件（有测试 = Claude Code 有自我校验的尺子，无需你介入就能验证结果）；遇到循环卡死（直接告诉它「这个方向走不通，原因是……换个思路」）。完成信号：你自测通过。

✓
Commit（提交）— 审查、生成信息、推送

你满意了才到这一步。两个好习惯：跑子 Agent 做代码审查（子 Agent 是全新实例，不继承主会话偏见，能更客观地发现问题）；让 Claude Code 生成提交信息（告诉它你的提交风格，它会根据实际改动生成准确描述）。完成信号：代码已推送。

四步工作流感觉有点繁琐，简单任务也要走完整流程吗？
不需要。按复杂度弹性使用：简单改动（改一行文字、修一个明显 bug）直接提示，不用 Plan Mode；中等任务（加一个功能）建议至少走 Plan 步骤；复杂任务（新功能模块、架构变动）强烈建议完整走四步。越复杂、越不可逆，前期计划的收益越高。
子 Agent 代码审查是什么意思？
Claude Code 支持启动一个独立的子 Agent 来审查代码。子 Agent 是全新的 AI 实例，不继承主会话的上下文——所以它不会因为「自己写的代码」而产生确认偏差，能更客观地发现问题。在提交之前让子 Agent 跑一遍，相当于让一个没有参与过开发的同事做 Code Review。

总图与速查

5.1 全局概念地图

Claude Code 是一个 Agent——它通过 Agent Loop 自主运转：你输入 Prompt，Harness 驱动模型调用 Tools，工具执行结果经由 Write-back 写回对话历史，模型据此决定下一步，直到任务完成。Context Window 是这个循环的记忆边界，Permission 模式决定你在循环中的介入程度。下图展示了这些概念之间的层级关系：

5.2 核心概念速查

Agent
能自主多步骤规划和执行的 AI 系统。Claude Code 是一个以编程为专长的 Agent。
Agent Loop（Agent 循环）
发送消息 → 模型响应 → 执行工具 → 写回结果 → 重复，直到模型认为任务完成。
Write-back（写回）
把工具执行的真实结果放回对话历史，让模型「看见」现实世界的反馈，这是循环能自我修正的关键。
Harness（驾驭层）
驱动循环的外层代码，负责维护历史、执行工具、写回结果。Claude Code 本身就是一个 harness。
Context Window（上下文窗口）
模型在一次对话中能「看到」的全部内容上限。Claude Code 会在接近上限时自动压缩历史。
Tools（工具）
赋予模型与现实交互能力的接口——读文件、写文件、跑命令、搜网页。没有工具，模型只能「说话」。
Permission（权限）
控制 Claude Code 行动前是否需要你确认。Default 逐步审批，Auto-accept 自动通过，Plan Mode 只读。
Plan Mode（计划模式）
只读状态，Claude Code 探索代码库并制定方案，不做任何修改。用 Shift+Tab 切换。
